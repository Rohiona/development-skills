# Coding Style

- **Immutability**: 既存オブジェクトを直接変更せず、変更を含む新しいコピーを返す。隠れた副作用を防ぎ、デバッグと並行処理の安全を保つため
- **エラー処理は境界に置く**: エラーを黙って握りつぶさない。UI 向けは分かりやすいメッセージ、サーバー側は詳細ログ。エラー処理・検証はシステム境界（ユーザー入力・外部 API・外部データ）に置き、内部コードとフレームワークの保証は信頼する（CLAUDE.md「過剰実装をしない」と整合）
- **入力検証は境界で**: 外部データを信頼しない。スキーマベースの検証で早期に・明確なメッセージで失敗させる
- **ファイル構成**: 少数の大きなファイルより、凝集度の高い小さなファイル。機能/ドメイン単位で整理する
- **実装完了時の自己点検**: extract-testable-module の責務自己評価を一度通したか（厚い private・長大関数・関心混在。なければ「妥当」で通過可。発火忘れ防止）

# Token Economy: 文脈を汚さない取得・探索

毎セッションの文脈（コンテキスト）は有限の予算。次の2つで「読みすぎ・探しすぎ」を防ぐ。

- **WebFetch で公式ドキュメント・長い Web ページを取るとき、全文を文脈に載せない。** prompt に「〜の節/設定値/API シグネチャだけ抽出して返す」と要点を指定し、必要部分だけ受け取る。ページ全体の把握が必要なら要約を先に取り、深掘りは節単位で追加取得する（1回 10KB 超の全文流入が頻発した実測: 2026-07-04 環境調査）。
- **当たりの付いていない広い探索（grep/find の反復・複数ディレクトリの走査）は、メイン文脈で直接撃たず Explore／general-purpose サブエージェントへ委譲して結論だけ回収する。** 当たりが付いている単発の検索・確認はメインで直接やってよい（委譲の往復の方が高くつくため）。
- **長い成果物（レビュー結果・handoff・長文分析・大きな一覧）は1つの応答に直接出さず、ファイルに書いてチャットには要約と参照パスだけ返す。** 応答が出力上限を超えるとセッションが丸ごと失われる実害が出ている（insights 実測 2026-07-04: 複数セッションが復元不能・128分の作業消失例）。

# Security Guidelines

- **秘密情報をソースにハードコードしない**（API キー・パスワード・トークン）。環境変数か secret manager を使い、起動時に必須シークレットの存在を検証する。露出した可能性のあるシークレットは即ローテーションする
- **セキュリティに影響する変更は必ず専門レビューを通す**: auth/authz・ユーザー入力・DB クエリ・外部 API・支払い・インフラ権限に触れる変更は security-reviewer agent／レビューのセキュリティ波が必須（インジェクション・XSS・CSRF・認可バイパス等の網羅チェックはそちらが正本）
- **セキュリティ問題を見つけたら**: 即停止 → security-reviewer で評価 → CRITICAL を先に修正 → 露出シークレットをローテーション → 同種問題をコードベース横断で確認

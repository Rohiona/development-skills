# 三者協議（Claude 進行・Codex⇄Cursor ファイルベース議論）

Claude が進行役兼「2 対 1」の主（1）となり、**Codex と Cursor（2）を共有ファイル上で直接議論させて**、
間接的に三者合意へ収束させるスキル。**他人の意見を先に聞かせない（せーの）** を核に、まず各 AI に独立開陳
させてから突き合わせる。Claude の見解は最初は伏せ、独立開陳後に注入する。エージェント間通信は agmsg を
使わず、`/tmp` の議論ディレクトリ＋内側ドライバ `scripts/discuss-inner.sh` で行う。

## 核となる原則: 「他人の意見を先に聞かせない」（せーの）

このスキルの肝は **まず各 AI に自力で考えさせ、出揃ったところで“せーの”で突き合わせる** こと。
先発の意見に後発が引きずられるアンカリング（早すぎる礼儀的合意の主因）を構造的に排除する。
合意も反論も「自分・相手・人間(Claude)の見解をメリット/デメリットで比較し、理由づきで納得したときだけ」許す。

## 構成（2 対 1）

- **議論を回す 2 人 = Codex と Cursor**（内側ループ）。互いに対等な議論者。
- **主 = Claude（メイン・あなた）が 1**（外側ループ）。headless にはならず、議題提示・自分の見解の注入・
  内側結論への反論差し戻し・最終統合を担う。Codex/Cursor が 2 人で合意しても、Claude が論理的に反論すれば
  差し戻す＝「2 対 1」で 1 人でも筋が通れば押し戻せる。

## 仕組み（2 層ループ）

- **外側ループ = Claude が回す（コンテキストに載る）**: 議題提示（自分の見解は **伏せて** 渡す）→ 内側議論を
  起動 → 結論だけ読む → **反論があれば論理的に整えて差し戻す（ラリー）**。Claude の文脈に乗るのは
  **自分の見解＋各サイクルの結論だけ**。生の往復は読まないので、Claude の発言は各サイクルの結論に対する反応である
  （＝逐ラウンド論戦ではない。トークン節約との両立）。
- **内側ループ = `discuss-inner.sh` が回す（コンテキストに載せない）**: 次の 3 フェーズ。
  1. **独立開陳（ブラインド・並列）**: Codex と Cursor が【互いを見ずに】topic だけで独立見解を出す。
  2. **せーの開示 ＋ Claude 見解の注入**: 両者の独立見解を同時に俎上へ載せ、続けて `claude-view.md`
     （Claude の見解・反論）があれば注入する。これで 3 見解が揃う。
  3. **議論**: Codex⇄Cursor が 3 見解を比較し、理由づき合意のみで収束させる。**先攻はラウンド交代**
     （奇数=Codex/偶数=Cursor。先攻固定の系統バイアスを除去）。各ターンは末尾に
     `AGREE_ON:` / `REMAINING_OBJECTIONS:` / `RESOLVED:` の 3 タグ必須（欠落時 1 回だけ再要求）で、
     driver が**「yes は残存相違 none のときだけ有効」を機械強制**（礼儀的 yes を弾く整合ゲート）。
     Round 3 以降のプロンプト文脈は「独立開陳＋Claude 見解＋中間ラウンドのタグ要約＋直前ラウンド全文」に
     圧縮しトークンを抑える（transcript.md は全文ログのまま＝観戦・distiller は不変）。
  Claude は **生の往復を読まない**。読むのは status（1 行）と conclusion.md（終結時のみ）だけ。
  conclusion.md 末尾には**最終ラウンドの各自の宣言タグが機械抽出（改変なし）で付記**される —
  distiller 要約と食い違うときは**タグ側が正**（要約ズレの低コスト照合手段）。

## 大前提（最初に必ず意識し、報告でも正直に伝える）

- **Codex も Cursor も自走しない**。`codex exec` / `cursor agent -p` は 1 回起動して 1 回返すだけ。
  「両 AI が勝手に往復し続ける」は成立しない。ターンは必ず誰かが回す＝内側はスクリプト、外側は Claude。
- **「直接対話」はファイル＋ターン進行で再現したもの**。各 AI が相手の生発言をファイルから読む点が、
  Claude が要約中継するより忠実（Claude のバイアスが混ざらない）。
- **トークン節約は Claude のコンテキストの話**。Codex/Cursor の起動自体は実コスト（Agent SDK
  クレジット / Cursor クレジット）を食う。**往復回数 × サイクル数がそのまま課金**になるので、
  内側上限 K と外側上限 M を必ず守る（既定 K=4, M=3）。無制限ループは禁止。
- **Claude は生の議論を読まない＝結論を検証せず中継する**。conclusion.md を書いた AI が誤要約しても
  Claude は気づけない。閣下への最終報告では必ず「**これは AI 側の自己申告結論で、私は生の往復を
  読んでいない**」とラベルする（epistemic-honesty）。生の往復まで裏取りしたいと言われたときだけ
  transcript.md を Read する（その分トークンを食う旨を伝える）。
- 両 AI とも **read-only**（Codex `-s read-only` / Cursor `--mode ask`）。議論は意見出しのみ、副作用なし。

## 手順

### 0. 誤発火ガード・論点確認（送る前に必ず）

次の 2 つを独立に判定し、不足があれば**ブラインドで起動せず**閣下に確認する:

- **(i) AI 協議か、閣下本人との壁打ちか断定できない**（相手 AI の指定が無く文脈も薄い）:
  「(A) AI 同士で協議 / (B) 私（Claude）との壁打ち」のどちらかを確認して分岐。
  ※ description のトリガー「壁打ちを AI 同士で」は **AI 同士**を指す。閣下と Claude の 1 対 1 壁打ちは対象外。
- **(ii) 協議すべき論点が特定できない**（相手が明確でも論点が空のとき含む）:
  論点が空のままキックオフしない。**会話文脈から論点・前提が一意に定まるときのみ具体化してよい。
  少しでも曖昧なら閣下に確認する（確認に倒す）**。文脈が薄いまま自前で論点を仕立てて起動しない
  （ブラインド起動は実コストを空費する）。

### 1. 議論ディレクトリと「対象コードベース」を用意し、議題と（伏せた）自見解を書く

```bash
SLUG="$(date +%s)-<topic-keyword>"        # 例: 1718500000-wf-delivery
DIR="/tmp/sansha-kyogi/$SLUG"
mkdir -p "$DIR"

# 【重要】コードベースを協議するときは、いま作業中の worktree/ブランチの root を必ず取得して渡す。
# これを渡さないと Codex/Cursor は実コードを読めず（議論 dir しか見えず）、机上の空論になる。
REPO="$(git rev-parse --show-toplevel 2>/dev/null || pwd)"   # 例: /Users/.../Projects/<プロジェクト>
# コードと無関係の一般論（設計思想の壁打ち等）を協議するときだけ REPO="-"（コード無し）にする。
```

- **両 AI は同一の `REPO`（＝このセッションが今いる worktree のパス）を作業ルートにする**。だから
  Codex も Cursor も**まったく同じコードベース・同じブランチ**を read-only で見て議論できる。別 worktree や
  別ブランチを混ぜない（食い違いの元）。`REPO` は `git rev-parse --show-toplevel` で worktree root を取る
  （サブディレクトリで起動しても repo root に揃う）。

Claude は **2 つのファイルを分けて** 書く（せーの原則: Codex/Cursor に Claude の立場を先に見せない）。

**`topic.md`（Codex/Cursor に渡る・Claude の立場は含めない）**:

- **論点**（何を協議するか・一文）
- **対象コードベース**（`REPO` のパスと現在ブランチ。例: `/Users/.../echo @ feat/xxx`）を1行明記
- **前提・事実**（確定事項、制約、関連 file:line。冗長にしない）
- **求める出力**（賛否・理由・代替案・リスク等、AI に何を返してほしいか）
- ❌ **Claude 自身の見解・結論は書かない**（書くと独立開陳が Claude に引きずられる）

**`claude-view.md`（任意・Claude の見解。フェーズ2 で注入される）**:

- Claude（三者の 1 人としての主）の見解と理由。**独立開陳が終わってから** 俎上に対等に載る。
- 省略可（純粋に Codex/Cursor の議論だけ見たいとき）。あれば driver が自動で注入する。
- 外側ループ 2 周目以降は、ここに **前サイクル結論への反論・新論点** を書いて差し戻す（ラリー）。

### 2. 内側議論を background で起動する

> **前提（必読）**: この手順は **メインの Claude セッションで実行する**。内側ドライバを subagent
> （Agent ツール / dispatch 配下）の background で起動すると、ドライバがターン境界で死に、
> status=RUNNING のまま空 transcript になる（実証済み）。**subagent dispatch 不可。**

Claude は **Bash の `run_in_background: true`** で内側ドライバを起動し、**完了通知を待つ**
（生の往復は読まない・待機中はトークンを食わない）:

```bash
~/.claude/skills/sansha-kyogi/scripts/discuss-inner.sh "$DIR" "$REPO" 4 codex 600
#                                                        DIR    REPO   K  distiller timeout(sec/call)
```

- **第2引数 `$REPO` が肝**: ここに worktree のパスを渡すと、Codex(`-C`)・Cursor(`--workspace`)とも
  そのコードベースを作業ルートにし、実コードを read-only で読みながら議論する。コード無しの一般論協議は
  `"-"` を渡す。議論コンテキスト(topic / claude-view / transcript)はドライバがプロンプトに inline 埋め込みで
  渡すので、両 AI は「実コード ＋ これまでの議論」を両方踏まえて発言できる。

- **ドライバの内部進行**: 起動すると driver はまず **独立開陳（Codex/Cursor をブラインドで並列起動）** を行い、
  次に両者の独立見解＋`claude-view.md` を俎上へ載せ（せーの）、その後 **議論フェーズ（下記 `K` 往復）** に入る。
  起動側（Claude）が意識するのは引数だけでよい。

**【必須】起動した直後に、待機へ入る前に、ライブ観戦用の tail コマンドを閣下へ必ず提示する。**
`$DIR` を実際のパスに展開した、そのままコピペで打てる形で出すこと（変数のままにしない）。例:

```
🔭 ライブ観戦（任意）: 別ターミナルで議論をリアルタイムに見られます（Claude のトークンは消費しません）
   tail -f /tmp/sansha-kyogi/1718500000-wf-delivery/transcript.md
```

これは「閣下が見たい場合の任意導線」だが、**提示自体は毎回必須**（見るかどうかは閣下が決める）。
外側ループで新 DIR を作って再起動するたびに、その**新しいパスで** tail コマンドを出し直すこと。

- **待ち方**: `run_in_background: true` で起動するとツールは即座にタスク ID を返す。スクリプトが
  終了（status を書いて exit）すると harness が**完了通知を自動で送ってくる**ので、それを待ってから
  手順3へ進む。**待機中に transcript を Read したり status を polling/sleep で叩いたりしない**
  （メインセッションはターンをまたいでも生き続けるので、ただ通知を待てばよい＝待機中はトークン非消費）。

- `K`（**議論フェーズ**の往復上限）= 既定 4（独立開陳はこれと別に必ず 1 回先行する）。
  `distiller`（結論を書く担当）= **サイクルごとに codex/cursor 交代**（偏り防止: 第1サイクル codex、第2サイクル cursor、…）。
- 第4引数 `600` は **各エージェント1回の呼び出しに掛ける timeout 秒**（全体実行の上限ではない）。
  片側が固まっても per-call timeout で打ち切られ、議論は次へ進む。
- スクリプトは独立開陳の後 Codex⇄Cursor を交互に走らせ（先攻はラウンド交代）、**両者の末尾宣言が
  `RESOLVED: yes` かつ `REMAINING_OBJECTIONS: none`（整合ゲート通過）になったら status=REACHED**、
  上限到達なら status=CAPPED を書いて終了する。**status は完走時に必ず REACHED/CAPPED へ確定する**
  （スクリプトは `set -e` 非依存で最後まで走るため）。`RUNNING` が残るのは**完走せず死んだとき**だけ
  ＝手順3の異常系。

> **ライブ観戦は閣下の端末専用**: 上記 tail は閣下の端末に流れるだけで **Claude のコンテキストには
> 一切載らない＝トークンコスト ゼロ**。逆に **Claude 自身は絶対に transcript を tail / Monitor / Read しない**
> （生往復を文脈に載せると節約思想が崩れる）。Claude が見るのは終結後の status と conclusion.md だけ。

### 3. 終結フラグだけ確認 → 終結時のみ結論を読む

完了通知後、**status（1 行）だけ**確認する:

```bash
cat "$DIR/status"     # REACHED / CAPPED
```

- `REACHED` or `CAPPED` のときだけ `conclusion.md` を Read する（**transcript.md は読まない**）。
- conclusion.md は 1 サイクル分の要約なので軽い。**末尾の機械抽出タグ（最終ラウンドの各自の宣言）と
  要約本文を必ず突き合わせる** — 食い違うときはタグ側が正（distiller の要約ズレを検知したら報告に明記）。
- **異常系**: `status` ファイルが無い／中身が `RUNNING` のまま／空のときは **起動失敗**とみなす
  （precondition 失敗で `discuss-inner.sh` が status 生成前に exit、または subagent 配下で死亡した等）。
  この場合 **conclusion.md は読まず**、「内側議論が起動・完了しなかった」と正直に報告する。原因切り分けが
  必要なら `$DIR` の有無・`cursor`/`codex` の導通・`topic.md` の存在を確認する。

### 4. 外側ループ — Claude が「3 人目」として毎サイクル必ず見解を述べる（収束 or 上限まで）

conclusion.md を読んだら、**Claude は毎サイクル必ず「第 3 の参加者」としての実質的な見解を表明する**
（種まきして終わりにしない。これが二者協議に堕さないための肝）。手順は:

1. **【必須】Claude の第 3 者見解を作る**: conclusion.md（＝Codex⇄Cursor の到達点）に対して、
   **賛成/反対/部分同意のいずれかを明示し、理由・見落とし・追加論点・リスクを述べる**。単なる
   「同意」で済ませず、3 人目として議論に実質を足す（コードベース協議なら自分でも該当コードを
   確認して根拠を持つ）。これは合意していても必ず行う。
2. **収束判定**:
   - **AI が REACHED かつ Claude にも実質的な異論・追加が無い**（＝3 者の見解が揃った）→ 収束。手順 5 へ。
     ※「異論が無い」は手順1で実際に吟味した結果であること。吟味せず自動同意しない。
   - **CAPPED（AI 間で未合意）／ Claude に異論・追加がある** → 次サイクルへ。
3. **次サイクルの起動**: **新しい SLUG/DIR を作って手順 1 から再実行**する（`discuss-inner.sh` は
   transcript.md を `>>` 追記するため、同一 DIR 使い回しは前サイクルの往復が混ざる＝新サイクルは必ず新 DIR）。
   - 新 `topic.md`: 論点＋前提＋**前サイクルの結論の要点**＋事実（**Claude の立場は依然書かない**＝
     新サイクルでも独立開陳をアンカリングさせない）。
   - 新 `claude-view.md`: **前サイクル結論への Claude（主）の反論・新論点**を書く（＝差し戻し＝ラリー。
     せーので Codex/Cursor が再度独立開陳した後に、この反論が俎上へ載る）。
   - 手順 2 で `distiller` を入れ替える。
4. **外側サイクルが M=3 に達したら打ち切る**（未収束でも手順 5 へ。残った相違点と Claude の立場を報告）。

> これにより Claude は「開幕の種まき＋各サイクル境界での実質的な第 3 者発言＋最終統合」を担う真の参加者になる。
> ただし**生の往復（transcript）は読まない**ままなので、Claude の発言は各サイクルの結論に対する反応である
> 点は変わらない（トークン節約との両立）。逐ラウンドで論戦に割り込む完全 3 者モードが要るときだけ、別途
> 閣下に相談して transcript を読む高コスト運用に切り替える。

### 5. 閣下へ統合報告

- **合意点 / 未解決の相違点 / 各 AI の主張の要点 / Claude の推奨** を整理して返す。
- **どこまでが AI の自己申告結論（事実：conclusion.md 由来）で、どこからが Claude の統合・判断（推論）か**を
  区別する。「生の往復は読んでいない」旨を明記する。
- 生ログ（transcript.md）や各サイクルの成果物は `$DIR` に残っている旨を伝える（必要なら閣下が直接読める）。

## 起動コマンド早見

| 役割 | コマンド |
|---|---|
| 内側議論（background 起動） | `~/.claude/skills/sansha-kyogi/scripts/discuss-inner.sh "$DIR" "$REPO" 4 <codex\|cursor> 600`（`$REPO`=対象 worktree パス / コード無しは `"-"`） |
| 終結フラグ確認 | `cat "$DIR/status"` |
| 結論（終結時のみ Read） | `$DIR/conclusion.md` |
| 生ログ（原則読まない・裏取り依頼時のみ） | `$DIR/transcript.md`, `$DIR/r<N>.<agent>.md` |

## 注意

- **上限を必ず守る**: 内側 K=4 / 外側 M=3。これは実コスト（クレジット）の上限。勝手に増やさない。
  論点が重く増やしたいときは閣下に相談してから。
- **Claude は transcript.md を原則読まない**（トークン節約の核）。読むのは status と conclusion.md だけ。
  例外: 閣下が「生の議論を見たい／結論を裏取りして」と言ったときのみ Read（コスト増を伝える）。
- **相手不在・失敗の握りつぶし禁止**: codex/cursor が空応答・エラーのとき、transcript には
  `(no output …)` が残る。conclusion が空なら status と併せて「片側が応答しなかった」と正直に報告する。
- **2 者だけで回したい場合**（例「Codex とだけ」「Cursor とだけ」）: 三者協議の枠ではないので、
  単発なら `codex` skill / 直接 `cursor agent -p` を使う。本スキルは Codex⇄Cursor の議論が前提。
- ディレクトリは `/tmp/sansha-kyogi/<slug>/` 固定（使い捨て・read-only 議論なので安全）。
  対象リポジトリや他の作業ディレクトリには触らない。

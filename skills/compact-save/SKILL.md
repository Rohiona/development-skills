# compact-save: 圧縮前の状態保存

/compact の要約は「何をやったか」は残すが「なぜ・どれを却下したか・今どのフェーズか」を
落とす。この skill はその落ちる情報だけを圧縮の外側（ファイル）に固定する。
**手順は上から順に厳守。スキップ・順序入替え禁止。**

## 手順

### 0. レビューセッション判定（入口ゲート・2026-07-23 閣下決定）

`pwd` と `git rev-parse --abbrev-ref HEAD` で、このセッションがレビュー用かを機械判定する:

- cwd が `.claude/worktrees/` 配下で、ワークツリー名が `review/` 配下 or `*-review-*` を含む
- または ブランチ名が `review/*` / `claude/review/*` / `*-review-*` に一致

**該当した場合**: 保存に進む前に次を伝えて停止する —
「このセッションはレビュー用です。レビュー文脈は使い捨て（diff 断片・所見・試行錯誤）が大半で、
compact の要約は肝心の SHA・ブロッカーを落とすリスクがあるため、**compact ではなく
handoff → /clear が既定**です。handoff を実行しますか？」
ユーザーが「それでも compact する」と明示したときだけ手順 1 へ進む。
**非該当なら**そのまま手順 1 へ（この判定結果は報告しなくてよい）。

### 1. セッション ID の取得（Hard gate）

```
bash ~/.claude/scripts/get-session-id.sh --verify "<直近のユーザー発話から抜いた特徴的な10〜20文字>"
```

- `--verify` には、この skill を起動させた直近のユーザー発話の一部（他セッションに
  出なさそうな特徴的な部分文字列）をそのまま渡す。同一ディレクトリで並行セッションが
  動いていても自セッションの transcript だけが一致するため、誤爆を防げる。
- 出力が空、または exit code が 0 以外 → **state file を作らずここで停止**し、
  「セッション ID を特定できないため保存を中止しました」と報告する。
  推測したファイル名で保存してはならない（復旧 hook が別ファイルを読む事故になる）。
- 以後 `<SID>` = 取得した ID。保存先は `~/.claude/session-state/<SID>.md`（固定）。

### 2. 材料の収集

- **TaskList** を実行し、タスクの状態（未着手/進行中/完了）を確認する。
- 進行中の plan があれば（plan mode 中・plan 文書があれば）その内容・パスを確認する。
- `git status --short` と `git rev-parse --abbrev-ref HEAD` で編集中ファイルとブランチを確認する。
- バックグラウンドで動いているもの（Monitor・常駐タスク・並走サブエージェント・レビュー等）を
  会話文脈から洗い出す。
- **既存の state file があれば先に Read する**（再圧縮のケース）。前回の判断ログのうち
  まだ有効なものは新しいファイルへ引き継ぐ。無効になったものは捨てる。
  ※「前回ファイルの要約」を書かない。生きている判断だけを個別に転記する（入れ子劣化の防止）。

### 3. state file の書き出し

`~/.claude/session-state/<SID>.md` に、**次の見出しをこの順で全部**含めて Write する。
該当が無い節も見出しは残し「なし」と書く（見出しの欠落 = 保存漏れの検知子）。

```markdown
# セッション引き継ぎ状態（compact-save）
保存日時 / cwd / ブランチ を1行で。

## 現在の作業と目的
何のために何をしているか。2〜4行。

## 現在フェーズ
今どの段階か（例: 調査完了→実装中→検証前）。「次にやること」と「まだやってはいけないこと」
（順序制約・承認待ち）を明記。plan mode 中ならその旨と plan の要点/パス。

## タスク状況
TaskList の結果を転記（ID・状態・内容）。

## 判断ログ（採用・却下・却下理由）
このセッションで下した判断を列挙。**特に却下した案と却下理由は必ず書く**
（圧縮後に却下案を再提案する事故の防止が本 skill の最重要目的）。
形式: 「採用: 〜（理由）」「却下: 〜（理由）」。

## 制約・ブロッカー
守るべき制約（触ってはいけない領域・スコープ宣言・ユーザーとの合意事項）と、
現在ブロックされている事項。

## バックグラウンドタスク・監視
並走中の Monitor / サブエージェント / Workflow / レビュー等の一覧と、それぞれの状態。
「なし」でも明記（圧縮後に存在を忘れて二重起動する事故の防止）。

## 編集中ファイル・ブランチ
git status の要点とブランチ名。未コミットの変更があれば何の変更かを1行ずつ。

## ユーザー指示の原文（新しい順・appendix）
このセッションでユーザーが出した指示・制約・好みの表明を、**言い換えずに原文引用**で
新しい順に列挙する（Codex 方式: 要約の質に依存せず指示を生き残らせる）。
重要なものに絞り最大 20 件・合計 150 行以内。古い/無効化された指示は含めない。
※ この節は appendix。復旧時は上の節（フェーズ・判断ログ・制約）が核であり、
この節は判断に迷ったときだけ参照される前提で書く（必ず最後の節の直前に置く）。

## 復旧メモ（圧縮後の自分への手紙）
圧縮後の自分が最初に読むべき注意を自由記述。ユーザーから引数で復旧メモを
渡されていればそれを最優先で書く。例: 「◯◯はやるな」「まず△△を確認」。
```

### 4. 読み返し検証（Forcing function）

書き出した state file を Read し、上記 10 見出しが**すべて**存在するか確認する。
欠けていれば追記して再度 Read で確認する。確認が取れるまで次へ進まない。

### 5. 完了報告

以下だけを簡潔に報告して終了する:
- 保存先パス
- 「準備完了です。**/compact を実行してください。**圧縮後は復旧指示が自動で入ります。」

※ この skill 自身が /compact を実行することはできない（ユーザー操作が必要）。
※ 保存内容を長々とチャットに再掲しない（コンテキストを無駄に使わない）。
